End-to-end system flow

The pipeline's 15 nodes sit in a single worker box; the stage-by-stage flow is in the state machine diagram. The weight here is on what surrounds the worker: which surfaces come in from where, which gates a run passes before it gets a slot, what the worker calls out to, how the heavy PDF path works, and where the result is written and how it gets back.

Admission before a run starts

  • One arq queue, three priority bands; the enqueue score is the queue position
  • CapacityGate measures Ollama's resident VRAM and hands out run slots against what is actually free
  • scheduler.py preempts: an urgent question pauses the running normal run and resumes it afterwards
  • Preemption acts across owners, so it takes a system principal — who gets paused is a scheduling decision, not something the requester is authorised to do

The heavy PDF path

  • pdf-inspector extracts the whole document first; the gate and the critic both read that one pass
  • GirisKapisi raises per-page flags (has_table, needs_ocr, has_figure); PDFCritic scores quality; the page selector decides what is worth re-extracting
  • Only the flagged pages are re-extracted. The tool for that is the docling service — a separate image because torch is several GB and five services share the app image
  • With the service off the run does not fail: fast-path text is kept and the document is marked degraded

One card, two consumers

  • Ollama and docling share the same RTX 4060; DOCLING_MAX_CONCURRENT=1 holds docling to one conversion at a time
  • CapacityGate reserves headroom for docling but cannot see it — resident_vram_gb only reports Ollama
  • DOCLING_DEVICE=cuda refuses to start without a card, deliberately: CPU and GPU do not produce the same text (7 of 261 pages differ, one loses a table) and content_hash is the sha256 of that text

Scope and corrections

  • The 15 LangGraph nodes collapse to one worker box — the stage flow has its own diagram
  • Per-stage Repository writes and _boundary() checkpoints are not drawn; they exist on every node
  • migrate is not drawn: it belongs to startup, not to the run flow
  • Corrected: the vector store is not Qdrant — embeddings live in the passages.embedding JSON column and similarity is computed in Python via _cosine
  • Corrected: the run endpoint is POST /v1/research-runs; there is no /api/v1/research/start
