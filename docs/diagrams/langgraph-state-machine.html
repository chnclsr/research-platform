LangGraph state machine

The 15-node graph the worker executes. The flow runs top to bottom; rows alternate direction, left-to-right then right-to-left. CHECK_COVERAGE is the only branch point and PLAN_RECOVERY → SEARCH the only loop.

CHECK_COVERAGE — the only branch

  • _coverage_route returns one of three keys: expand, finish, halt
  • expand → PLAN_RECOVERY, which returns to SEARCH and opens another round
  • finish → ADVERSARIAL_REVIEW and synthesis
  • halt → straight to END; when the budget runs out the run stops with the evidence it has

ACQUIRE and the parser

  • Five fetch strategies in order — _direct, scholarly metadata, agentsearch, crawl4ai, scrapling; first success wins
  • Anything under 400 characters is dropped, which is why a scanned PDF with no heavy engine disappears here
  • ParserRegistry.select() picks SmartPdfParser (priority 20); the heavy re-extraction it calls out to runs in the docling service
  • content_hash is the sha256 of the parsed text, so parsing has to be deterministic
